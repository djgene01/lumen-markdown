## 1. Strategy

Three layers, each with a clear owner:

| Layer | Scope | Runs | Owner |
|-------|-------|------|-------|
| Unit (automated) | Core: encoding, Markdown output, dirty hashing, settings, token classifier | Every build; < 5 s | Developer |
| Integration (automated, headless) | `TextFileLoader`/`Writer` against a temp folder; renderer against fixture files; settings schema migration | Every build; < 20 s | Developer |
| UI and manual (scripted) | Window behaviour, WebView2 preview, drag-drop, dialogs, DPI, Narrator, performance | Each phase gate and before release | Developer + user |

**Non-goal for v1:** automated UI-driving (WinAppDriver/Appium). The tooling cost and flakiness outweigh the value for a single-window app; manual scripts are scripted tightly instead and re-run at each gate.

## 4. Unit and integration cases (selection)

### 4.1 Encoding (T-ENC)

| Case | Input | Expected |
|------|-------|----------|
| UTF-8 no BOM | `café` bytes | Text `café`, encoding UTF-8, no BOM added on save |
| UTF-8 BOM | EF BB BF prefix | BOM not shown as characters; BOM preserved on save |
| UTF-16 LE/BE | with BOM | Decoded correctly; saved back in same encoding |
| Invalid byte | 0xFF in text | Replacement char + warning flag set |
| NUL byte | binary blob | `BinaryFileException`, no text returned |
| Mixed EOL | CRLF and LF | Dominant EOL detected; save normalises per policy |
| 10 MB + 1 byte | large file | `FileTooLargeException` with size |

### 4.2 Markdown (T-RENDER)

Each fixture asserts presence/structure of: headings `h1..h6`, paragraphs, emphasis, strong, inline code, fenced code with language class, block quote, ordered/unordered/nested lists, task list checkboxes, table header/body/alignment, footnote reference/backlink, autolink, strikethrough, horizontal rule, image with alt, relative link preserved.

Negative cases: raw `<script>` appears as **escaped text**, not an element; unclosed fence does not swallow the rest of the document character-for-character incorrectly; 2 000-level nested block quote is capped without stack overflow.

### 4.3 Dirty state (T-DIRTY)

- Open → edit → undo to original ⇒ `IsDirty == false`.
- Edit → save ⇒ hash matches original ⇒ clean.
- Edit → Save As new path ⇒ clean, path updated, recents updated.
- External write while dirty ⇒ `Stale`, dirty preserved.

### 4.4 Atomic write (T-SAVE)

- Write to temp in the same directory, `File.Replace`, original preserved on failure injection (read-only directory).
- Line endings: CRLF file saved with CRLF; LF with LF; mixed uses dominant.
- Read-only attribute: write fails with `UnauthorizedAccessException` mapped to a friendly error, file unchanged.

### 4.5 Settings (T-SET)

- Missing file ⇒ defaults, file created on first change.
- Unknown `schemaVersion` ⇒ backup + defaults, no crash.
- Truncated JSON ⇒ backup `settings.bad.json` + defaults.
- Recent list > 10 ⇒ trimmed oldest-first; duplicates collapse to most recent.
- Save is debounced and atomic; killing the app mid-save leaves either old or new file, never a truncated one.

## 5. UI test scripts

### 5.1 Smoke (every phase gate, 5 minutes)

1. Launch from `dotnet run`; window appears within 2.5 s.
2. Open `fixtures/markdown/showcase.md`; both panes populated.
3. Type "test"; preview updates; dirty dot appears.
4. Ctrl+S; dot clears; close and reopen; "test" persisted.
5. Toggle each layout; switch theme; resize to minimum; close.

Pass = no dialog other than expected, no console/`logs` error, no visual clipping.

### 5.2 Full acceptance script (release, 45 minutes)

Follow [10-Acceptance-Checklist.md](10-Acceptance-Checklist.md) top to bottom on the clean VM. Record pass/fail and a screenshot for each failed item.

### 5.3 Accessibility script (T-A11Y)

1. Keyboard-only: reach and invoke every command without a mouse.
2. Narrator: command buttons announce name; editor announces as editable text; status changes are not noisy.
3. Accessibility Insights: no missing names, no contrast failures in light/dark/high-contrast.
4. Text scale 200 %: no clipped command bar, no overlapping status text.
5. Focus visible at all times; Esc never traps focus in the find bar.

## 6. Performance measurement

| Metric | Method | Pass |
|--------|--------|------|
| T-PERF-01 cold start | `Process.Start` timestamp → first `MainWindow.Activated` logged; 5 runs | median ≤ 2.5 s |
| T-PERF-02 open 1 MB | Stopwatch around load+first render; log both | ≤ 1.0 s |
| T-PERF-03 keystroke→preview | Log t0 on TextChanged, t1 on WebView2 `DOMContentLoaded`/message ack; 200 keystrokes | p95 ≤ 300 ms |
| T-PERF-04 typing lag | Manual + frame gaps while typing 1 MB | no gap > 50 ms perceived |
| T-PERF-05 memory | `Process.WorkingSet64` after 5 min with 1 MB open | ≤ 350 MB |

Record results, machine spec, and build hash in `docs/performance.md`. A failed target is a Phase 6 defect, not a footnote.

## 7. Soak and failure injection

**Soak (30 min):** loop of open → type 200 chars → scroll → toggle layout → toggle theme → find → save → close, on a 100 KB document. Pass = zero unhandled exceptions, working set stable (± 20 %), no orphaned WebView2 processes after close.

**Injection matrix**

| Injection | Expected |
|-----------|----------|
| File deleted while open | Save offers Save As; no crash |
| File locked by another process | Save shows "file is in use", keeps edits |
| Disk full (small VHD) | Save fails cleanly; temp file removed |
| Read-only folder | Save As blocked with message |
| WebView2 runtime removed | Banner, app still edits and saves |
| Corrupt settings | Defaults + backup |
| Rapid open/close x50 | No handle leak, no crash |
| Monitor unplugged mid-drag | Window repositions onto remaining display |

## 8. Capturing failure diagnostics (before changing architecture)

When a phase check fails, capture in this order:

1. **Repro**: file used, exact steps, expected vs actual, screenshot.
2. **Log**: `%LOCALAPPDATA%\LumenMarkdown\logs\app-YYYYMMDD.log` tail.
3. **Exception**: full `ToString()` including inner exceptions and stack.
4. **Build**: `dotnet --info`, `dotnet build -bl` binlog path, package versions from `project.assets.json`.
5. **Environment**: Windows build (`winver`), display scale, WebView2 runtime version (`Get-AppxPackage *WebView2*` or registry), .NET runtimes.
6. **Event Viewer**: Application log entries for the app and `.NET Runtime`.

Only after those are attached should a design change be proposed. "It didn't work" is not a diagnosis.

## 10. What is deliberately not tested in v1

- Automated UI automation (see §1).
- Fuzzing of the Markdig parser (upstream responsibility; our fixtures cover malformed input).
- Multi-user or concurrent-editing scenarios (out of scope).
- Windows 10 and ARM64 (out of scope per UD-2).
